## P0 — Streaming Phase Loop Extraction (HIGHEST IMPACT)

### Problem
`api/streaming.py` contains its own phase execution loop (~180 lines) that duplicates `application/flows/runner.py:WorkflowRunner.run_phase()`. The streaming loop handles SSE I/O, keepalive, retry, quality, and error logging — all of which the WorkflowRunner already does.

### Target State
`streaming.py` delegates ALL phase lifecycle concerns to `WorkflowRunner`. Streaming becomes a pure SSE adapter: build events, yield them, handle cancellation. No business logic about retry count, quality thresholds, or phase ordering.

### Files to Touch

| File | Change | Lines affected |
|------|--------|---------------|
| `application/flows/runner.py` | Add `sse_callback` parameter to constructor | +5 |
| `application/flows/runner.py` | Add `get_critical_phases` static helper | +10 |
| `application/flows/runner.py` | Add `run_phase_with_keepalive` method | +50 |
| `api/streaming.py` | Replace inline phase loop with `runner.run(strategy, state)` | -180 |
| `api/streaming.py` | Move `_PHASE_ROLE_HINTS` to runner (already extracted to `phase_executor.py`) | — |
| `api/streaming.py` | Move `CRITICAL_PHASES` computation to runner | -20 |
| `api/streaming.py` | Keep SSE event builders (`_event`, `_broadcast_ws`, `_persist_event`) | Keep ~100 lines |

### Step-by-Step

#### Step 1: Prepare WorkflowRunner for SSE callbacks

File: `application/flows/runner.py`

**Current signature:**
```python
class WorkflowRunner:
    def __init__(self, services: WorkflowServices, monitor: PhaseMonitor | None = None):
```

**New signature:**
```python
class WorkflowRunner:
    def __init__(self, services: WorkflowServices, monitor: PhaseMonitor | None = None,
                 sse_callback: Callable[[dict], None] | None = None,
                 cancel_event: asyncio.Event | None = None,
                 keepalive_interval: float = 15.0):
```

The `sse_callback` is called with event dicts whenever a phase lifecycle event occurs (start, complete, error, quality result, retry). If `None`, no SSE events are emitted (CLI mode).

#### Step 2: Move keepalive logic to runner

`WorkflowRunner.run_phase_with_keepalive` handles:
- Run the phase function
- Yield keepalive SSE comments every `keepalive_interval`
- Cancel if `cancel_event` is set
- Timeout if phase exceeds deadline

This is currently in streaming.py as a closure `_run_phase_with_keepalive`. Move it as a method.

#### Step 3: Add SSE event emission in runner

During phase execution, call `sse_callback` at:
- Phase start → `{"type": "phase_start", "phase": n, "name": name, "models": models}`
- Phase complete → `{"type": "phase_complete", ..., "data": {...}}`
- Phase error → `{"type": "error", "error_type": ..., "message": ...}`
- Phase retry → `{"type": "phase_retry", ...}`
- Phase quality → `{"type": "phase_quality", "score": ..., ...}`

#### Step 4: Replace streaming.py phase loop

**Current (streaming.py, ~lines 540-720):**
```python
for num, name, fn, serializer in phases:
    # SSE: yield start
    # compute CRITICAL_PHASES
    # run _run_phase_with_keepalive
    # catch errors, handle retries
    # quality check
    # SSE: yield complete
```

**Target:**
```python
runner = WorkflowRunner(services, monitor,
                        sse_callback=lambda ev: yield _event(ev),
                        cancel_event=cancel_event,
                        keepalive_interval=15.0)
await runner.run(strategy, state)
# All SSE events emitted by runner via sse_callback
```

#### Step 5: Remove dead code from streaming.py

After replacement, remove:
- `_PHASE_ROLE_HINTS` dict (moved to `phase_executor.py` — already done)
- `_get_phase_start_models` closure (moved to phase_executor.py — already done)  
- `_run_phase_with_keepalive` closure
- `_run_phase_cancellable` closure (unused)
- `_LEGACY_CRITICAL` set (moved to phase_executor.py — already done)
- `CRITICAL_PHASES` computation (moved to `get_critical_phases` in phase_executor.py — already done)
- `_PHASE_ROLE_HINTS` usage
- Import of `get_phase_retry_budget`, `get_phase_timeout` from constants (if only used in extracted code)

## P2 — Event-Sourced Pipeline Execution

### Problem
PipelineState (mutable dataclass) and PipelineAggregate (event-sourced) coexist. Events are a side channel for observability, not the source of truth.

### Target
PipelineAggregate becomes the canonical state. PipelineState becomes a read projection. All mutations go through `aggregate.record_event()`.

### Approach
**Incremental** — the optimized plan from `architecture-refactoring-plan-v3-optimized.md`. Do not do a full rewrite. Instead:

1. Extend PipelineAggregate with all fields currently in PipelineState
2. Have `ReasonerPipeline.run()` work with PipelineAggregate internally
3. Build PipelineStateReadModel from aggregate for SSE serialization (backward compat)
4. Keep PipelineState as a compatibility read model for 1 release cycle
5. Remove PipelineState direct mutation after migration is confirmed stable

This is 1 week of high-risk work. Do not start until P0 and P1 are complete and verified.

## P3 — OpenTelemetry Tracing

### Approach
1. Install `opentelemetry-api`, `opentelemetry-sdk`, `opentelemetry-instrumentation-fastapi`
2. Add manual spans at key boundaries:
   - `PipelineOrchestrator.execute()` → `pipeline.run`
   - Each phase → `phase.{name}`
   - Each LLM call → `llm.call` with model, role, tokens attributes
   - EventBus publish → `event_bus.publish`
3. Correlation IDs: generated at pipeline start, propagated via span baggage
4. Export to Jaeger (dev) or OTLP collector (prod)
5. SLO alerts: p95 phase duration > 120s, error rate > 1%
