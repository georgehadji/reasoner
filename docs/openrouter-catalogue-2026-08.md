# OpenRouter Catalogue Refresh — August 2026

Snapshot fetched 2026-08-16, **447 models** — from *both* lanes:
`GET /api/v1/models` (text, 413) and `?output_modalities=image` (45, overlapping 11).
Bundled as `src/reasoner/domain/openrouter_models.json`, regenerated by
`scripts/update_openrouter_catalogue.py`.

---

## 1. What was broken

### `PRICING_DB` was empty in every deployment

`domain/pricing.py` builds `PRICING_DB` by loading `openrouter_models.json` from its
own directory. **That file was never committed** — it only ever existed as a local
scratch dump at the repo root (see `extract_image_models.py`, `.dockerignore`).

Measured before the fix:

```
PRICING_DB entries: 1
['_default']
```

So `get_pricing()` returned the `_default` fallback of **$1.00 / $5.00 per M for every
model**, and everything downstream inherited that: `pricing_service`,
`budget_ceiling`, `utility_scorer`, credit metering, the `/estimate` endpoint and the
per-run cost figures in the UI. A `gpt-4o-mini` synthesis call was billed as if it
were 6.7× its real input price; `deepseek-v4-flash` as if 16×.

After: **414 entries**, real prices.

### Three dead model pins

| Alias | Old target | Fix |
|---|---|---|
| `ling-3.0-flash-free` | `inclusionai/ling-3.0-flash:free` | → `inclusionai/ling-3.0-flash` ($0.021/$0.063). The `:free` tier died exactly as the code comment predicted. |
| `qwen-image-3` | `qwen/qwen-image-3` | Removed — Qwen has no image-output model on OpenRouter any more. |
| `qwen-image-3-pro` | `qwen/qwen-image-3-pro` | Removed — same. |

Only Google and OpenAI ship image-output models now. Both image `-preview` pins were
promoted to GA ids (`google/gemini-3-pro-image`, `google/gemini-3.1-flash-image`) —
same price, 131K context instead of 65K.

Every other pin in the whitelist resolves to a live model. The seven `~vendor/name`
auto-updating aliases are real and were verified individually.

## 2. Preset changes indicated

50 presets reference 41 distinct aliases. All 41 resolve. The presets share one
"budget block" and one "premium block" of role assignments, so a handful of swaps
propagate very widely.

### Tier 1 — strict upgrades (cheaper or equal, newer model)

| Role · uses | Current | Recommend | Delta |
|---|---|---|---|
| `meta_evaluator`, `verifier`, `perspective_cot` (41×) and the `gemini-flash-lite` budget primary (15×) | `qwen3.5-flash` $0.065/$0.26 | **`qwen3.7-flash`** $0.03/$0.13 | **−54%**, newer gen, same 1M ctx, gains vision |
| `synthesis` (44×) | `gpt-4o-mini` $0.15/$0.60, 128K ctx | **`gpt-5.6-luna`** $0.10/$0.60, 1.05M ctx | −33% input, 8× context, current generation instead of a 2024 model |
| `stress_testing`, `verifier`, premium primary (44×) | `grok-4.3` $1.25/$2.50, 1M ctx | **`grok-4.20`** $1.25/$2.50, 2M ctx | identical price, double context † |

† `grok-4.20` drops `stop`, `frequency_penalty` and `presence_penalty` from its
supported parameters. Verified harmless: the OpenAI-compat provider sends none of the
three — `LLMRequest` declares the penalties (`infrastructure/llm/ports.py:114`) but no
call site forwards them, and no stop sequences are constructed anywhere in the LLM
layer. `temperature` and `top_p` are both supported, so per-phase temperatures survive.
| `image_generate` | `gemini-3-pro-image-preview` | `gemini-3-pro-image` | identical price, 131K vs 65K ctx — *already applied* |

`gpt-4o-mini` is the single highest-leverage line in the whole registry: it is the
final synthesized voice in 44 preset slots, and it is the oldest model still in
routing.

The `gpt-5.6` `-pro` siblings (`sol-pro`, `terra-pro`, `luna-pro`) are priced
**identically** to their base tiers on OpenRouter. Wherever a base tier is used, the
`-pro` variant is a free capability upgrade. All three added to the registry.

### Tier 3 — cross-bloc integrity

- **EU representation is thin.** Across 50 presets the EU bloc appears in five slots
  total: `ministral-8b` (2×, which actually resolves to
  `mistralai/mistral-small-3.2-24b-instruct`), `mistral-large-3` (2×),
  `mistral-small-2603` (1×). Invariant B (generators span ≥2 blocs) holds, but it
  holds narrowly. At $0.50/$1.50, `mistral-large-2512` is now cheap enough to serve
  as a real premium generator anchor rather than a token EU presence.
- **Alias collision not covered by the constraint.** `gemini-pro` resolves to
  `anthropic/claude-sonnet-5` — the same served model as `claude-sonnet`. In

## 3. Batch API

OpenRouter now exposes **61 `:batch` variants**, generally at 50% of interactive price
with asynchronous submit-and-poll delivery. Not usable for the SSE pipeline, which is
interactive by construction. It *is* usable for the async `/agent/run` endpoint and
for offline evaluation sweeps.

Batch lanes for models the presets already use:

| Model | Interactive | Batch |
|---|---|---|
| `anthropic/claude-sonnet-5` | $2/$10 | $1/$5 |
| `openai/gpt-4o-mini` | $0.15/$0.60 | $0.075/$0.30 |
| `minimax/minimax-m3` | $0.30/$1.20 | $0.15/$0.60 |
| `google/gemini-3.1-pro-preview` | $2/$12 | $1/$6 |
| `google/gemini-3.1-flash-lite` | $0.25/$1.50 | $0.125/$0.75 |

Two traps:

- **`z-ai/glm-5.2:batch` costs more than interactive** — $0.70/$2.20 vs $0.308/$0.968,
  and caps at 512K ctx vs 1M. Noted inline in the registry.
- The `gpt-5.6-terra` / `gpt-5.6-luna` batch lanes carry **no discount** — batch price
  equals base price. Only `sol` actually halves.

Batch is not worth adopting for the interactive pipeline. It is worth adopting for
evaluation runs, where the same prompt set is replayed across many models.

## 4. The image lane — a catalogue bug that cost us models

`GET /api/v1/models` returns the **text lane only**. Pure image generators are
invisible unless you pass `?output_modalities=image`. There are **45 image-output
models**; the default listing showed 11.

Every one of these registry comments was wrong, and each deleted a working model:

```
# Removed: black-forest-labs/flux.* (all 4 models) — provider gone from OpenRouter
# Removed: sourceful/riverflow-v2-* (all 5 models) — provider gone from OpenRouter
# Removed: bytedance-seed/seedream-4.5 — not on OpenRouter
# Removed: x-ai/grok-imagine-image-quality — not on OpenRouter
# Removed: microsoft/mai-image-2.5 — not on OpenRouter
# Removed: recraft/recraft-v4* (all 8 models) — provider gone from OpenRouter
```

All are live. The deletions came from diffing against the default listing.
`update_openrouter_catalogue.py` now fetches both lanes and merges; the catalogue
went 413 → **447** entries.

Two structurally different kinds live under the registry's "image" heading:

| Kind | Pricing | Example |
|---|---|---|
| Hybrid chat+image | `prompt`/`completion` per token, plus `image_output` | `google/gemini-3-pro-image` $2/$12 per M |
| Pure generator | **no** `prompt`/`completion` at all — `image` / `image_token` only | `qwen/qwen-image-3` $0.003/image |

`_trim()` originally required `prompt` and `completion`, so every pure generator was
dropped from the catalogue and would have priced at zero. Fixed.

Restored / added: `qwen-image-3`, `qwen-image-3-pro`, `seedream-5-pro`,
`seedream-5-lite`, `grok-imagine-image-2`, `krea-2-large`, `krea-2-medium`,
`krea-2-medium-turbo`.

Per-image cost, cheapest first: Krea medium-turbo → Krea medium ≈ qwen-image-3 →
seedream-5-pro/qwen-image-3-pro ($0.003/image) → grok-imagine-image-2 ($0.01/image,
3.3× the Seedream/Qwen tier). `image_generate` currently routes to
`gemini-pro-image`; the $0.003 tier is a real alternative when a text-grounded
hybrid model isn't needed.

## 5. Six models evaluated for preset use

### `x-ai/grok-4.6` — $2/$6, 500K ctx, text+image+file, released 2026-08-12
xAI's current flagship: *"smartest model with frontier performance on coding,
knowledge work, and STEM."* Same price and context as `grok-4.5`, same parameter
support — a drop-in replacement for it.

**Where:** not as a swap for `grok-4.3`. The premium presets use `grok-4.3` for
`stress_testing` and `verifier`, where 1M–2M context matters more than raw STEM
strength; 4.6 halves the context and costs 1.6×/2.4× more. Use 4.6 where reasoning
depth is the binding constraint — `coding-premium`, `scientific-premium` and
`pot-premium` (Program-of-Thoughts) generation roles. **Retire `grok-4.5`** in its
favour: identical price, identical capability surface, newer.

### `google/gemini-3.7-flash` — $0.375/$1.875, 1M ctx
The widest input surface in the budget tier: **text + image + video + file + audio**,
with `reasoning_effort` support. Half the price of `gemini-3.6-flash`, an eighth of
what the registry claimed 3.6 cost.

**Where:** the strongest candidate for premium `deep_read` and `meta_evaluator`.
`deep_read` is `gemini-pro-real` ($2/$12) in 21 slots — 3.7-flash is **5.3× cheaper
on input, 6.4× on output** for the same 1M context and the same US/Google bloc, so
the cross-bloc invariant is untouched. Also the natural home for any multimodal
ingestion path, since it is the only budget-tier model here that accepts audio.

### `google/gemini-3.7-flash:batch` — $0.1875/$0.9375
Exactly half price. **Do not use in the pipeline.** Its `supported_parameters` drop
both `temperature` and `top_p`:

```
non-batch: ... seed, stop, structured_outputs, temperature, tool_choice, tools, top_p
batch:     ... seed, stop, structured_outputs,              tool_choice, tools
```

Reasoner sends per-phase tuned temperatures, gated by the substring denylist
`_FIXED_TEMPERATURE_MARKERS` in `providers/openai_compat.py:168`. No `:batch`
variant matches that denylist, so temperature would be sent and rejected. Any batch
adoption needs that denylist made data-driven off `supported_parameters` — which the
bundled catalogue now carries, so the fix is available but not yet wired.

### `qwen/qwen3.8-2.4t-a95b` — $2/$6, 1.05M ctx, text only, released 2026-08-12
Open-weight sparse MoE, 95B active of 2.4T total. Per its model card the open-weight
counterpart of `qwen3.8-max` with *"comparable performance"*, aimed at *"coding,
research, complex reasoning, and agentic workflows."*

**Where:** narrow. Priced identically to `qwen3.8-max`, which additionally accepts
image and video, so on OpenRouter `max` dominates it on capability at equal cost. Its
value is reproducibility — open weights mean a run can be replayed off-platform,
which matters for the event-sourced replay story and for `scientific-*` presets where
a falsification step should be auditable. Not a routine routing choice.

### `qwen/qwen3.8-27b` — $0.45/$3.20, 262K ctx, text+image+video, released 2026-08-14
Dense (not MoE) 27B vision-language model with toggleable thinking. Note the
asymmetry: cheap input, **expensive output** — $3.20/M puts its output above
`qwen3-max-thinking` ($3.90 is only 1.2× more) despite being a far smaller model.

**Where:** input-heavy, output-light roles only. That is exactly `scoring` and
`verifier` — they read a lot and emit short structured judgements. It would be a poor
choice for `synthesis` or any generator role, where output dominates. Given
`glm-5.2` at $0.308/$0.968 covers the same CN bloc more cheaply on both sides, this
model is only interesting where its **vision/video input** is needed.

### `deepseek/deepseek-v4-pro-0813` — $0.435/$0.87, 1M ctx
The dated pin still carrying v4-pro's **old** price. The rolling
`deepseek/deepseek-v4-pro` is now $1.168/$2.336 — **2.7×** more for the same model
family. Across the 37 `deepseek-v4-pro` preset slots that is the single largest
avoidable cost in the premium tier.

**But it cannot currently be routed.** `build_provider()` treats any alias whose
resolved vendor is `deepseek` as direct-API:

```python
is_deepseek = model_id.startswith("deepseek-") or _vendor_of(model_id) == "deepseek"
```

and `api.deepseek.com` rejects dated suffixes — the same failure already documented
inline for the retired `-0731` pin. So a `deepseek-v4-pro-0813` alias would 400
whenever `DEEPSEEK_API_KEY` is set, and there is no per-entry opt-out from the direct
lane. Capturing this price needs a `"force_openrouter": True` flag on the registry
entry, honoured in `build_provider`. Recommended, but it is a code change, not a
routing change — hence not applied here.

## 6. Keeping it fresh

```bash
python scripts/update_openrouter_catalogue.py          # refresh in place
python scripts/update_openrouter_catalogue.py --check  # exit 1 + diff if stale
```

The `--check` mode prints added/removed model ids and is suitable for a scheduled CI
job — dead pins in this repo have historically been found only after a run failed in
production.
