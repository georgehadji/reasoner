## 0. Executive Summary

**Reasoner** is a production-grade, event-sourced, multi-method AI reasoning orchestrator that decomposes complex problems into structured multi-phase pipelines, leverages 164+ LLM models from diverse training ecosystems in parallel, applies independent critique, stress-tests solutions, and synthesizes actionable recommendations with epistemic labeling (`VERIFIED` / `HYPOTHESIS` / `UNKNOWN`).

| Attribute | Value |
|-----------|-------|
| **Architecture Style** | Hexagonal DDD + CQRS + Event Sourcing + Workflow Strategy Composition |
| **Backend** | Python 3.12+, FastAPI 0.109+, Pydantic v2, ~402 source files |
| **Frontend** | Next.js 16 (App Router), React 19, TypeScript 5, Tailwind CSS v4 |
| **State Model** | `PipelineState` (~60 fields) + `PipelineAggregate` (event-sourced) |
| **LLM Routing** | OpenRouter primary (350+ models), 12+ direct provider adapters, Ollama local |
| **Reasoning Methods** | 30 (multi-perspective, debate, jury, research, scientific, socratic, pre-mortem, bayesian, dialectical, analogical, delphi, cove, sot, tot, pot, self-discover, writing) |
| **Presets** | 50+ declarative presets (budget, balanced, premium, experimental tiers per method) |
| **Models Supported** | 164+ (from OpenRouter: Anthropic, OpenAI, Google, xAI, Perplexity, Mistral, DeepSeek, Qwen, Kimi, GLM, MiniMax, Xiaomi, plus local Ollama) |
| **Web Search** | SearXNG (self-hosted Docker) + Perplexity Sonar |
| **Memory** | Neuro L1/L2/L3 tiered cache with embedding search + Cohere rerank |
| **Security** | Input sanitization, prompt-injection defense, rate limiting, scoped auth, CSRF, circuit breaker |
| **Self-Healing** | AST-based introspection engine + auto test generation + CI/CD coverage gating |
| **v3.0 Refactor** | Mixin-based God Object → Workflow Strategy pattern; sys.modules race condition eliminated |

## 3. Layered Architecture (Hexagonal DDD + CQRS)

### 3.1 Dependency Flow (Inward Only)

```
API Routes → Application (CQRS Handlers, Flows, Services)
              ↓
          Core (Protocols, Events, Aggregates, Constants)
              ↓
Domain (Business Rules, Presets, State Models)
              ↓
Infrastructure (Adapters: LLM, Persistence, WebSocket, Widgets)
```

**Key Principle:** Dependencies point inward. Domain has zero outer dependencies. Application depends on Domain/Core. Infrastructure implements Ports defined in Core.

### 3.2 Known Violations (Documented in CLAUDE.md)

| Violation | Location | Impact |

## 4. HyperGate Pre-Router (Request Classification)

Every incoming problem passes through **HyperGateAgent** before any reasoning pipeline. This lightweight classifier makes a fast, deterministic routing decision.

### 4.1 Architecture

```
Problem → [5 parallel sub-agents running concurrently]
           ├─ LanguageDetectorSubAgent     (identify language, script)
           ├─ ComplexityEstimatorSubAgent  (simple/moderate/complex)
           ├─ DirectDetectorSubAgent       (instant answer detection)
           ├─ WebSearchDetectorSubAgent    (web search necessity)
           └─ MethodClassifierSubAgent     (reasoning method A–Q letter code)
           
           ↓ (all outputs collected)
           
           TieBreakerSubAgent (if conflict or low confidence)
           
           ↓ (final decision)
           
           GateDecision:
           ├─ method: "B"–"Q" (opaque method ID)
           ├─ web_search: bool
           ├─ complexity: "simple" | "moderate" | "complex"
           ├─ language: str
           └─ confidence: 0.0–1.0
```

### 4.2 Sub-Agent Roles

| Sub-Agent | Input | Output | Confidence Metric |
|-----------|-------|--------|-------------------|
| **Language Detector** | Problem text | language code, script type, confidence | Regex/script match strength |
| **Complexity Estimator** | Problem text, language | simple/moderate/complex, reasoning | Feature count, keyword density |
| **Direct Detector** | Problem text, language | DIRECT / PIPELINE, confidence | Regex pattern match + TF-IDF |
| **Web Search Detector** | Problem text, language | needs_web_search (bool), confidence | Temporal keywords, event indicators |
| **Method Classifier** | Problem text, complexity, language | method letter (B–Q), confidence | Keyword/intent matching |

### 4.3 Creative Writing Fast-Path

If `_is_creative_writing(problem)` returns True (pure creative, no research required), the decision is:
- **Route:** DIRECT (no HyperGate call needed)
- **Executor:** Writing method with direct answer (no search, no multi-phase)

### 4.4 Real-Time Query Detection

Temporal patterns (price/news/weather/live scores + temporal markers like "now", "today", "live"):
- **Route:** WEB_SEARCH (live Perplexity Sonar)
- **Executor:** Research method or web-aware fallback

### 4.5 Fallback Behavior

If any sub-agent fails (network error, LLM timeout, exception):
- **Result:** SubAgentOutput with error=str(exc), confidence=0.0
- **Impact:** TieBreaker uses non-errored agents only; if all fail, default to "multi_perspective" preset

## 5. Core Pipeline Flow (6 Phases)

After HyperGate routing decision, the pipeline executes **Phase 0–5** (or method-specific variant).

```
Phase 0: Classification
├─ Task Type (research, creative, decision, prediction, analysis)
├─ Problem Language
├─ Constraints & Success Criteria
└─ Output: TaskType enum

Phase 1: Decomposition
├─ Identify ≤5 sub-problems
├─ Enumerate failure modes
├─ Generate working assumptions
└─ Output: Decomposition with SubProblems

Phase 2: Multi-Perspective Generation (parallel)
├─ Constructive (positive, forward-looking)
├─ Destructive (adversarial, failure modes)
├─ Systemic (cross-domain, interdependencies)
├─ Minimalist (parsimonious, core insight)
└─ Output: 4 GenerationCandidates (or top-k after scoring)

Phase 3: Critique & Pruning
├─ Independent scoring (0–10) per candidate
├─ Retains top-k candidates (default k=2)
├─ Explicitness, coherence, novelty, risk assessment
└─ Output: CritiqueScores, pruned candidate set

Phase 4: Stress Testing
├─ Optimal-case scenario
├─ Constraint-violation scenario (edge cases)
├─ Adversarial scenario (worst assumptions)
└─ Output: StressTestResults (robustness metrics)

Phase 5: Synthesis
├─ Epistemic labeling (VERIFIED / HYPOTHESIS / UNKNOWN)
├─ Action blueprint (next steps, dependencies)
├─ Risk summary + epistemic caveat
└─ Output: FinalSolution (synthesized answer + metadata)
```

### 11.4 Circuit Breaker

```python
class CircuitBreaker:
    state: "CLOSED" | "OPEN" | "HALF_OPEN"
    
    async def call(provider: LLMProvider, ...) → response:
        if self.state == "OPEN":
            if time.now() > reset_timeout:
                self.state = "HALF_OPEN"
            else:
                raise CircuitBreakerOpenError(provider)
        
        try:
            result = await provider.complete(...)
            self.state = "CLOSED"  # Success
            return result
        except ProviderError:
            self.failure_count += 1
            if self.failure_count > threshold:
                self.state = "OPEN"
            raise
```

```typescript
async function parseSSEStream(
  response: Response,
  onEvent: (event: PipelineEvent) => void
) {
  const reader = response.body?.getReader();
  const decoder = new TextDecoder();
  
  while (true) {
    const { done, value } = await reader!.read();
    if (done) break;
    
    const chunk = decoder.decode(value);
    for (const line of chunk.split('\n')) {
      if (line.startsWith('data: ')) {
        const json = JSON.parse(line.slice(6));
        onEvent(json);
      }
    }
  }
}
```

## 21. v3.0 Refactoring Changes

### 21.1 Mixin Composition → Workflow Strategy

**Before (v2.x):**
```python
class ReasonerPipeline(
    DebateMixin, JuryMixin, ResearchMixin, ...:  # 17 mixins!
):
    async def run(self, problem: str) -> PipelineState:
        ...
```
**Problem:** God Object, method resolution order (MRO) complexity, tight coupling.

**After (v3.0):**
```python
class ReasonerPipeline:
    def __init__(self, ...):
        self.flow_factory = WorkflowFactory()
        # ...
    
    async def run(self, problem: str) -> PipelineState:
        method = determine_method(...)  # HyperGate decision
        flow = self.flow_factory.get_workflow(method)
        return await flow.run(state)
```

**Benefits:**
- Single Responsibility: each flow class has one method
- Composition over inheritance
- Easier testing and extension
- No MRO surprises

### 21.2 sys.modules Race Condition Fix

**Issue:** During parallel sub-agent execution, `sys.modules` import cache could be corrupted by concurrent module imports.

**Fix:** Lazy imports in sub-agent `__init__` → imports happen in correct async context, no races.

### 21.3 Event Sourcing Integration

- All pipeline runs now emit domain events
- Full audit trail persisted
- State reconstruction from event log
- Recovery from crashes (resumable pipelines)
